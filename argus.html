ARGUS Air & Radiant-temperature Guard Using Sensors

ESP32-S3 IoT & C++ Embedded Web Dashboard Multi-Sensor

1. Hardware Assembly & Power Circuitry

ESP32-S3 microcontroller integrated with DHT22 temperature/humidity sensor, MQ-2 gas sensor, infrared flame detector, buzzer, and a 3.7V 18650 Li-Ion backup battery circuit.

2. Embedded C++ Firmware & Alarm Logic

Non-blocking sensor polling, multi-stage buzzer escalation logic, local Wi-Fi Access Point routing, and persistent threshold storage using ESP32 Non-Volatile Storage (NVS).

3. Embedded Web Dashboard & Real-Time Telemetry

On-chip HTML/JS monitoring interface hosted at 192.168.4.1 featuring live 60-second temperature dot-matrix charts, humidity ring gauge, sensor health status, and threshold controls.

About The Project

Enclosed operational spaces, such as server rooms, laboratories, warehouses, and production floors, are vulnerable to unnoticed gas leaks, smoke accumulation, and abnormal temperature spikes. Manual inspections rely heavily on human presence, often causing critical delays in early hazard detection.

Developed by Kelompok ETA (Electronics & Instrumentation, Universitas Gadjah Mada), ARGUS is an ESP32-S3-based IoT environmental and fire early-warning prototype. It continuously monitors ambient air, combustible gases, and infrared flame radiation while hosting a self-contained web dashboard over local Wi-Fi.

Goals

  • Providing continuous, automated monitoring of ambient temperature, relative humidity, combustible gas/smoke, and infrared flame presence.
  • Delivering real-time telemetry and visual alerts via an embedded web dashboard without requiring external cloud dependencies.
  • Ensuring uninterrupted operation during main AC power outages through an integrated Li-Ion backup power system.
  • Allowing operators to customize and persist safety alarm thresholds directly on the microcontroller's non-volatile memory.

The User & Audience

The system is engineered for facility operators and technical personnel responsible for critical indoor infrastructure:

  • Facility & Laboratory Operators: Technicians monitoring server racks, chemical storage rooms, or laboratory equipment who need immediate visual and acoustic warnings upon environmental anomalies.
  • Embedded & Instrumentation Engineers: Developers requiring reliable multi-sensor acquisition, sensor fault diagnostics, and local JSON API telemetry for rapid edge deployment.

System & Hardware Scope

  • Multi-Sensor Acquisition: Combines a DHT22 digital sensor (GPIO 6) for temperature (−40 to 80°C) and humidity (0–99.9% RH), an MQ-2 semiconductor sensor (GPIO 7 ADC with 20kΩ/10kΩ voltage divider) for LPG/smoke detection, and a digital Infrared Flame Sensor (GPIO 15).
  • Embedded Web Dashboard & JSON API: Runs an on-chip HTTP web server and captive portal on ESP32-S3 (192.168.4.1) serving a responsive UI that polls /api every 2 seconds for live charts, heat index calculations, and sensor health status.
  • Multi-Stage Acoustic & Visual Alarm: Drives a 1 kHz active buzzer (GPIO 13) and color-coded dashboard flashes—escalating from a 1-beep/sec warning to a 2-beep alert, and locking into a latched critical alarm after 10 seconds of sustained threshold breach.
  • Persistent Threshold Configuration: Uses ESP32 Preferences (NVS) so custom temperature, humidity, and MQ-2 millivolt thresholds configured via the web UI survive device restarts.
  • Uninterruptible Power Architecture: Powered by 220V AC via a 5V adapter backed by a 3.7V 18650 Li-Ion battery, TP4056 CC-CV charging module, and MT3608 5V boost converter with relay switching.

Process

  • Hardware & Power Design: Mapped GPIO interfaces and designed a dual-source power rail with voltage division to safely step down the MQ-2's 5V analog output to the ESP32-S3's 3.3V ADC range.
  • Firmware & Non-Blocking Control Logic: Programmed non-blocking sensor polling (2-second intervals), sensor fault validation (SENSOR ONLINE vs. SENSOR ERROR), and time-staged buzzer patterns in C++.
  • Frontend Dashboard Integration: Built a lightweight HTML/CSS/JS interface embedded in PROGMEM featuring a 60-second temperature dot matrix, humidity ring gauge, and real-time threshold form.
  • Testing & Validation: Verified captive-portal Wi-Fi access, JSON API latency, threshold persistence across reboots, and sensor error handling under simulated fault conditions.
